# 私聊来源名称回归修复

## 原因与范围

统一总结工作台将私聊来源规范成 `uid_a@uid_b`，用于消息检索及权限校验。
原名称解析器却将完整会话 ID 当作单个用户 UID 查询，查不到后保存
`来源-xxxxxxxx(私聊)`。关闭工作台后，旧入口传入对方 UID，因此不触发这一差异。
修复位于后端，并非前端编码或字符集问题。

新工作台的预览保存、个人/多人工作流创建，均以可信的总结创建者身份解析
会话另一方的名字。保留原始来源 ID，不改变取消息和权限校验逻辑，
不信任客户端名称。格式错误、缺少创建者或创建者不在会话内时，不猜测用户名字。

读取列表、详情及创建新分享快照时，仅对空名称和符合该错误格式的规范私聊占位名称
进行实时解析。真实名称快照、群聊/子区名称规则、旧格式的非空名称、
已经创建的分享快照和数据库历史行均不改写；不需要数据库迁移。

## 回归覆盖

1. 私聊 ID 两种顺序、旧单用户 UID、未知用户、空名字、缺失 IM 数据库。
2. 无创建者、无关创建者、缺少一方、重复自身、多余分隔符安全降级。
3. 工作台保存及个人/多人工作流保存正确名字，同时保留规范会话 ID。
4. 创建者与参与者读取列表/详情时均使用创建者视角；新分享快照也正确。
5. 真实历史名称不变；只修复精确匹配的占位名称，读取不改写持久化数据。

验证命令（需要 CGO 和 libtokenizers）：

```sh
CGO_ENABLED=1 CGO_LDFLAGS="-L/path/to/libtokenizers -ltokenizers -lstdc++" \
  go test ./internal/service ./internal/api/handler ./internal/worker -count=1
```

2026-09-08 验证结果：上述三个包测试通过；`Dockerfile.api` 构建通过。
本地 28140 更新 API 后，原有总结中的 `来源-7ecf56dc(私聊)` 显示为
IM 中的 `总结参与者(私聊)`，无需重新生成总结。前端与 worker 镜像保持原样。
上述验证只涉及本地环境，未部署 test 或生产环境。
