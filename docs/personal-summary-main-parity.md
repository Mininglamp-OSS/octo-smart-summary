# Personal summary capability parity and reliable Agent submission

## Scope

Personal summaries saved by Agent and generated by Workflow share the existing
edit, version history, regeneration and scheduling services. Continue-optimize
still opens the Agent conversation and creates a new summary. This change does
not implement local-edit routing or change the evidence-retrieval strategy.

The paired frontend uses personal/team categories, exposes the existing personal
actions for both origins and reuses Workflow progress and streaming.

## Generation configuration and history

- Add nullable `summary_task.generation_requirement`, separate from the display
  title. Recover legacy Agent requirements only from an owned Agent run.
- Expose saved requirements in summary detail and allow authorized configuration
  updates through `PUT /api/v1/summaries/:id/generation-config`.
- Accept optional source/time configuration on the existing regenerate endpoint.
  Validate access and persist configuration without changing schedule recurrence.
- Save a personal-version baseline before regeneration and snapshots after edits;
  restore the last committed body when a single-person regeneration fails.
- Reset the stream lifecycle before rerunning the existing Workflow.

## Agent terminal submission

The planner calls `prepare_summary_draft({})` after gathering sufficient evidence.
A text-only writer receives authorized references, current preview, successful
Reduce text, conversation and effective scope. It does not receive planner
instructions or tool protocol.

The resulting Markdown is held under an immutable request-local `content_handle`.
The planner submits that short handle through `emit_summary_response`; the server
serializes the original `preview.content` response. Public response/SSE contracts
remain unchanged. Cross-request handles, inline bodies in live workspace runs,
unfinished Map/Reduce and invalid citations are rejected.

Malformed argument JSON is repaired locally at most twice without recording or
dispatching the invalid batch. After draft preparation only terminal submission
is allowed. Deterministic model/protocol failures are nontransient at the request
boundary, so they do not replay the entire completed run.

Optional run-scoped diagnostics record only structural metadata and hashes, not
prompts, argument values, credentials or user/channel names. Diagnostics are off
unless explicitly enabled for an exact run.

## Verification

```sh
go test ./internal/agent ./internal/llmfallback ./internal/service \
  ./internal/api/handler ./internal/worker ./internal/streaming
go test -race ./internal/agent \
  -run 'TestPreparedDraft|TestDraftWriter|TestToolArgument|TestInvalidArgument'
```

Tests cover configuration authorization/persistence, edit history, stream reset,
request-local handles, body fidelity, typed draft inputs, evidence gates,
bounded argument repair and nontransient error classification. Native library
paths must be configured for the local environment where required.

Separate private-clone real-model checks produced three cited reference-based
drafts and one complete fetch/Map/Reduce/draft/submission result. These checks are
not CI tests or a guarantee of model success. Private replay scripts, logs and
database snapshots are intentionally excluded from the repository.

## Rollout

Apply `migrations/sql/20260911-01-summary-generation-requirement.sql` through the
existing migration mechanism before serving the paired frontend. Deploy the
backend first. Back up existing data before migration; the down migration drops
the new configuration column and therefore discards saved requirements.

## CR follow-up

- Agent requests up to the chat limit remain intact in `generation_requirement`.
  Only the compatibility `topic` is rune-truncated to VARCHAR(2300); Agent
  Workflow execution reads the full saved instruction. Tests enforce the sink
  limit explicitly because SQLite does not enforce VARCHAR lengths.
- Malformed legacy assistant/tool batches are removed from planner input without
  modifying stored history. The strict outgoing/current-call guard remains.
  Tool-less post-draft responses receive at most two nudges, even at the final
  step; preparation argument repair is also allowed at the finalization budget.
- Streams are prepared before requeue commit, with fresh cleanup identity, idle
  expiry and rejection of the discarded run's start. Failure restores the exact
  pre-regeneration version; editing terminal failed/cancelled tasks is allowed,
  and manual edit snapshots obey the existing retention limit.
- The suggestion to mark exhausted draft failures transient at the request
  boundary is intentionally not adopted: `Client.Chat` already retries eligible
  model calls, while the browser's transient recovery restarts the entire turn.
  It cannot resume the request-local draft. Tests pin no full-run replay for
  exhausted transport/429/503 failures as well as protocol errors.
